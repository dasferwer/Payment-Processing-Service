# Фактически выполненные проверки

Дата: 8 октября 2026 года. Локальное окружение: macOS ARM64, Python 3.12.13, Docker Desktop. Проверки выполнялись с настоящими PostgreSQL 17 и RabbitMQ 4.1 из Compose.

## Результаты

- `uv run pytest -q`: **111 passed**, 0 ошибок. Каждый тест БД работал в отдельной схеме; брокерные тесты использовали отдельный vhost.
- `uv run ruff check app tests scripts migrations`: все проверки прошли.
- `uv run ruff format --check app tests scripts migrations`: форматирование проверено.
- `uv run alembic check`: нет расхождений между моделями и миграцией.
- На отдельной пустой БД выполнены upgrade head, check, downgrade base, повторный upgrade head и check. Временная БД удалена.
- `docker compose build` и `docker compose up -d --wait` выполнены. Полный стек также поднят с пустыми томами в отдельном временном Compose-проекте; проверены миграция и ответы API 401/404. Временный проект и его тома удалены.
- `uv run python -m scripts.verify_compose` выполнен на живом стеке; результаты — в `compose-results.txt`.
- После последних изменений API образ пересобран, полный Compose снова запущен, GET проверен HTTP-запросом на наличие Idempotency-Key в подробных данных платежа.

## Проверенные сценарии

API, Decimal и валидация JSON, конкурентная идемпотентность при 20 запросах, конфликт тела (в том числе boolean против number), атомарный откат при невозможности вставить outbox. Завершённое событие не обрабатывается повторно; повтор webhook сохраняет статус платежа. Проверены три попытки, общий бюджет при смешанных ошибках шлюза и webhook, экспоненциальные задержки, окончательный отказ и восстановление шлюза.

Проверены потерянный publisher confirm, недоступный маршрут, конкурентные публикаторы, пропуск отложенного события, persistent-сообщение, NACK/redelivery и настоящий маршрут в DLQ. Некорректный JSON, массив и числовой event_id отклоняются без блокировки следующего сообщения.

В полном Compose: успешное уведомление, временная ошибка и восстановление, три ошибки webhook и наличие сообщения в RabbitMQ DLQ; SIGKILL consumer во время шлюза и после фиксации платежа; восстановление только уведомления без повторной обработки завершённого платежа; отключение RabbitMQ, сохранение outbox и доставка после восстановления.

После аудита безопасности проверки повторены на обновлённых образах Alpine. На пустых томах подтверждены ограниченная роль БД и узкие права RabbitMQ, ответы API 401/404, upgrade/check/downgrade/upgrade/check. Отдельно выполнен `uv run python -m scripts.verify_broker_recreation`: persistent-сообщение сохранилось после пересоздания контейнера RabbitMQ. Добавлены проверки SSRF, DNS rebinding, TLS/SNI, утечек в логах, cookies, размеров и глубины JSON, дублирующихся заголовков, Unicode и предельных денежных сумм. Подробности и отчёты сканеров: [security-audit.md](security-audit.md).

## Границы проверки

Шлюз эмулируется согласно ТЗ; реальный платёжный провайдер не подключался. Инъекции технических ошибок шлюза и потерянного confirm проверены тестами; SIGKILL и отключение брокера проверены настоящими Docker-процессами. Webhook в тестах отправлялся локальному HTTP-получателю; внешний сервис клиента не проверялся.

Не проводились production-развёртывание, CI, нагрузочное испытание, проверка кластера RabbitMQ или аварийной потери диска. Реальные списания и exactly once для внешнего получателя не заявляются. Неопределённый ответ webhook допускает повтор доставки; аварийно откатившийся вызов не увеличивает счётчик завершённых попыток. Основной Compose-проект после проверки остановлен, его данные сохранены.
