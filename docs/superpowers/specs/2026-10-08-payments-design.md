# Асинхронный процессинг платежей

Источник требований: `requirements.pdf`, все три страницы; решения из переписки согласованы пользователем.

Четыре сервиса: PostgreSQL, RabbitMQ, API и один consumer. Публикатор outbox — фоновая задача consumer. API атомарно создаёт payment и outbox; уникальный ключ БД и сравнение нормализованного тела обеспечивают конкурентную идемпотентность, несовпадение даёт 409.

Каждое событие имеет UUID и ссылку на платёж. Публикатор блокирует готовую запись через FOR UPDATE SKIP LOCKED, ждёт publisher confirm и только затем фиксирует published_at. Consumer блокирует событие и платёж. completed_at защищает от дублей. Результат эмуляции шлюза сохраняется отдельной транзакцией до webhook. Повтор уведомления не запускает шлюз. Эмулятор ждёт 2–5 секунд и возвращает отказ в 10% случаев; он не списывает настоящие деньги.

Ошибки шлюза и доставки webhook имеют отдельные диагностические счётчики, но общий бюджет: максимум три попытки обработки события. Повтор создаётся через outbox в одной транзакции с завершением старого события, available_at = now + base * 2^(attempt-1). На третьей технической ошибке шлюза платёж становится failed; consumer уведомляет клиента и сохраняет диагностическое событие в DLQ. После третьей ошибки webhook результат платежа сохраняется, событие идёт в DLQ.

Webhook: POST JSON с payment_id, status, amount, currency, processed_at и metadata; успех — любой 2xx, redirects выключены. X-Webhook-Id стабилен для платежа. Доставка at least once: потеря ответа или сбой после приёма webhook допускает повтор; получатель должен дедуплицировать уведомления. Транзакция с блокировкой при внешнем вызове ограничена таймаутом. После аварии незавершённая транзакция откатывается, сообщение возвращается брокером.

API: Decimal, положительная сумма с двумя знаками, RUB/USD/EUR, UUID, UTC; обязательные X-API-Key и Idempotency-Key. Swagger и OpenAPI отключены, чтобы не оставлять незащищённых эндпоинтов. Только две таблицы, payments и outbox, миграции Alembic.

Проверки: API, конкурентные запросы и конфликт, атомарность, ошибка публикации и дубли confirm, повтор webhook без повторной обработки, сохранённые задержки, DLQ, авария consumer и восстановление, реальные PostgreSQL/RabbitMQ/Compose. Docker-ресурсы изолированы; существующие проекты не изменяются.
