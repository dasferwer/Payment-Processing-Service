# Аудит безопасности

Дата: 8 октября 2026 года. Проверено локальное решение из requirements.pdf: исходники, миграции, зависимости, контейнеры, API, PostgreSQL, RabbitMQ и webhook. Выполнены ручное ревью, независимое ревью надёжности, негативные тесты, сканирование и реальные аварийные сценарии. Это проверка конкретной версии в локальном окружении, а не доказательство отсутствия любых будущих уязвимостей.

## Обнаруженные проблемы и исправления

| Риск | Последствие | Исправление и проверка |
| --- | --- | --- |
| Высокий: произвольный webhook, внутренние IP и DNS rebinding | Чтение внутренних сервисов и отправка данных на небезопасный адрес | Политика публичных HTTPS-адресов, проверка всех DNS-ответов, закрепление IP, точный allowlist; негативные тесты IP-алиасов, смешанного DNS, redirects, реальный TLS/SNI |
| Высокий: PostgreSQL от имени bootstrap-superuser | Компрометация приложения открывала административный доступ к БД | Отдельная ограниченная роль приложения; проверены атрибуты роли, запрет pg_authid и свежая инициализация |
| Высокий: известные CVE в базовых образах и лишних инструментах | Уязвимые системные и служебные компоненты | Обновлены пакеты, минимальный многоэтапный Alpine-образ, удалены uv/pip из runtime и Go-бинарник gosu из PostgreSQL; повторное сканирование финальных образов |
| Средний: HTTPX INFO и SQL traceback | URL с токеном, metadata и параметры запросов могли попасть в логи | Отключены подробные сетевые логи и SQL-параметры; исключения журналируются без входных данных; тесты с контрольными строками |
| Средний: слишком большой/глубокий JSON и экстремальный Decimal | Ошибки 500, расход памяти или блокировка единственного consumer | Лимиты до обработки, bounded JSON, конечные числа, минимальная сумма 0.01; тесты chunked-тела, 5000-значного Content-Length, вложенности и Unicode; malformed AMQP отклоняется в DLQ |
| Средний: общий HTTP-клиент сохранял cookies | Получатель мог повлиять на следующий webhook | Новый клиент для каждой доставки, без переноса cookies; тело ответа не читается, redirects и env proxy отключены; проверено тестами |
| Средний: имя RabbitMQ зависело от контейнера | После recreate данные тома могли стать недоступны под новым именем узла | Стабильные hostname/nodename; реальное persistent-сообщение прошло force-recreate без потери |
| Средний: контейнер приложения с лишними правами и широкие права брокера | Расширение последствий компрометации | UID 10001, read-only, cap_drop, no-new-privileges, лимиты процессов/памяти/логов; права AMQP только на четыре нужных имени |
| Низкий: неоднозначные HTTP/JSON данные | Разное понимание ключей и обход проверок | Отклонены дубли API-key/Idempotency-Key/Content-Type/Content-Length и JSON-ключей; JSONB сравнение сохраняет различие true и 1 |

## Фактически выполнено

- 111 тестов прошли с настоящими PostgreSQL и RabbitMQ; Ruff и Alembic check прошли.
- Конкурентная идемпотентность: одинаковые и конфликтующие запросы, атомарный откат payment/outbox. Денежные границы, NaN/Infinity, metadata и строковые поля проверены негативными тестами.
- Три попытки, экспоненциальная задержка, общий бюджет технических ошибок, окончательный отказ шлюза, реальная DLQ, дубли и poison messages проверены.
- На живом Compose: webhook success/retry/exhaustion, SIGKILL во время шлюза и после commit, сохранение результата при повторе уведомления, недоступность RabbitMQ и восстановление outbox.
- Свежий Compose с пустыми томами: авторизация, ограниченная роль БД, права брокера, полный цикл миграций. Временные тома удалены; основные данные сохранены.
- pip-audit: 33 зависимости runtime, известных уязвимостей не найдено. Trivy: финальные образы приложения, PostgreSQL и RabbitMQ — без известных CVE на дату базы сканера.
- Bandit: только два LOW B311 для random в эмуляторе шлюза. Эти значения моделируют вероятность и задержку, криптографические секреты ими не создаются.
- detect-secrets: проверены файлы проекта, включая локальную конфигурацию. Найденные кандидаты — демонстрационные DSN/пароли, тестовые контрольные строки и идентификатор миграции. Необъяснённых секретов не обнаружено; это ручная классификация, а не нулевой результат сканера. `.env` имеет права 600 и не входит в образ.

Проверка контейнера подтвердила UID 10001, read-only rootfs, удаление capabilities, лимит 128 процессов/256 МиБ и публикацию API только на 127.0.0.1. В образе приложения отсутствуют `.env`, uv и pip. Финальный повтор тестов: `111 passed in 4.54s`.

Машиночитаемые результаты находятся в `docs/security/`. Для воспроизведения функциональных проверок используйте команды из README. Проверки аварий и пересоздания брокера предназначены только для этого демонстрационного Compose.

## Оставшиеся ограничения

Все граничные случаи перечислить и доказать невозможно. Сканеры покрывают известные базы уязвимостей и определённые классы ошибок; нулевой результат не исключает неизвестные CVE. Не выполнялись внешний pentest, нагрузочное испытание, проверка всех платформ, CI, кластерный failover и потеря диска.

По ТЗ используется общий статический API-ключ: отдельной изоляции клиентов, OAuth и квот на клиента нет. Локальные демонстрационные секреты необходимо заменить при эксплуатации. Входящий HTTP и AMQP внутри локального Docker не защищены TLS. Дополнительный периметр и секрет-хранилище в четыре сервиса не добавлялись.

Webhook передаёт metadata указанному получателю. Включайте в metadata только необходимые данные. Явно разрешённый origin считается доверенным административным исключением: HTTP передаёт данные без шифрования, внутренние адреса становятся доступны этому получателю. Проверка публичного DNS выполняется перед каждым соединением, но доступность и добросовестность внешнего получателя не гарантируются.

БД хранит платежи и ключи без срока удаления; шифрование томов, резервные копии и очистка логов вне заданных лимитов — ответственность эксплуатации. Администратор хоста/Docker может читать окружение и данные томов. Реального шлюза нет: гарантия неповторения настоящего списания требует идемпотентного контракта провайдера и сверки неопределённых результатов. Webhook остаётся at least once; получателю нужна дедупликация.

## Повторное сканирование

```bash
uv export --frozen --format requirements-txt --no-dev --no-hashes --no-emit-project -o /tmp/payments-runtime.txt
uvx pip-audit -r /tmp/payments-runtime.txt --no-deps --disable-pip
uvx bandit -r app
uvx detect-secrets scan --all-files --exclude-files '(^|/)(\.venv|\.pytest_cache|\.ruff_cache|__pycache__|docs/security)/'
docker save payment-processing-service-api -o /tmp/payments-api.tar
trivy image --input /tmp/payments-api.tar --scanners vuln
```

Trivy устанавливается отдельно из официального релиза с проверкой контрольной суммы. Аналогично проверяются образы `payment-processing-service-postgres:local` и `payment-processing-service-rabbitmq:local`. Для аудита использован Trivy 0.75.0; версия базы указана в `security/summary.json`. Образы и база обновляются, поэтому будущий результат может отличаться. Bandit возвращает ненулевой код из-за двух описанных LOW B311. Сканер секретов возвращает кандидатов для ручного разбора, а не подтверждённые утечки.
